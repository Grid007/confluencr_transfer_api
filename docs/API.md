# API reference

Interactive: `/docs` (Swagger UI) · Machine-readable: `/docs-json`, `/docs-yaml`, [openapi.json](openapi.json).

## Conventions

| Topic         | Rule                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------ |
| Versioning    | Business routes are under `/v1`. `/`, `/health`, `/docs*` are unversioned.                                   |
| Content type  | JSON only. Writes with another `Content-Type` get `415`. Bodies above 100 kb get `413`.                      |
| Field naming  | `snake_case` everywhere.                                                                                     |
| Money         | Always a JSON **string** with two decimals (`"150.00"`). Input may be a number or a numeric string.          |
| Timestamps    | ISO-8601 UTC with milliseconds (`2026-10-27T09:12:33.421Z`). Set by the server.                              |
| Ids           | Lowercase UUIDs, generated by the server. A malformed id is `400`; a well-formed unknown id is `404`.        |
| Resources     | Single resources are returned bare. Collections are `{ "data": [...], "meta": {...} }`.                      |
| Request id    | Every response has `X-Request-Id`. A well-formed client value (`^[A-Za-z0-9._-]{1,128}$`) is echoed.         |
| Unknown input | Unknown body fields and query parameters are rejected (`400`, rule `UNKNOWN_FIELD`), never silently ignored. |

### Order in which a request is checked

1. `415` media type → 2. `413` size → 3. `400 MALFORMED_JSON` → 4. `400` schema validation (all failing fields at once)
   → 5. `404` account existence (all missing accounts at once) → 6. `409` duplicate transfer → 7. `409` duplicate
   transaction → 8. `422` insufficient balance. The first failing stage is reported. As a consequence a replayed
   debit is always `409`, never `422`, even if the balance has dropped since.

### Error envelope

```json
{
  "error": {
    "status": 400,
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      {
        "field": "amount",
        "rule": "INVALID_AMOUNT",
        "message": "amount must be a positive decimal …"
      }
    ],
    "context": {},
    "request_id": "…",
    "timestamp": "…",
    "path": "/v1/transactions"
  }
}
```

`details` appears on `400` validation errors (one entry per failing field). `context` appears where noted below.
Nest's default `{ statusCode, message, error }` never reaches a client.

### Pagination

`GET /v1/accounts/{id}/transactions?type=&page=&limit=`

| Parameter | Rule                                                                   |
| --------- | ---------------------------------------------------------------------- |
| `type`    | Optional. Exactly `credit` or `debit` (case-sensitive). Omit for both. |
| `page`    | Integer ≥ 1, default `1`.                                              |
| `limit`   | Integer 1..100, default `20`.                                          |

Invalid values are rejected with `400 INVALID_PAGINATION`; they are never clamped. A page past the end is `200`
with `"data": []` and accurate `meta`. Ordering is `created_at` descending with an insertion-sequence tiebreaker.

```json
{
  "data": [
    {
      "id": "…",
      "account_id": "…",
      "type": "debit",
      "amount": "30.00",
      "description": null,
      "reference_id": "pay-7",
      "balance_after": "70.00",
      "transfer_id": null,
      "created_at": "2026-10-27T09:11:40.871Z"
    }
  ],
  "meta": {
    "current_page": 1,
    "page_size": 20,
    "total_records": 4,
    "total_pages": 1,
    "has_next": false,
    "has_previous": false
  }
}
```

## Endpoints

### `POST /v1/accounts` → `201`

Body: `{ "name": "Alice" }`. `name` is trimmed, 1..100 characters, no control characters. Anything else, including
`balance`, `id` or `created_at`, is rejected.

```json
{
  "id": "3f2504e0-4f89-41d3-9a0c-0305e82c3301",
  "name": "Alice",
  "balance": "0.00",
  "created_at": "2026-10-27T09:09:58.120Z"
}
```

Errors: `400 VALIDATION_ERROR`, `400 MALFORMED_JSON`, `413`, `415`. Sets a `Location` header.

### `GET /v1/accounts/{account_id}` → `200` (same shape as above)

Errors: `400 VALIDATION_ERROR` (`INVALID_UUID`), `404 ACCOUNT_NOT_FOUND`.

### `GET /v1/accounts/{account_id}/balance` → `200`

```json
{ "account_id": "3f2504e0-4f89-41d3-9a0c-0305e82c3301", "balance": "100.00" }
```

Errors: `400 VALIDATION_ERROR`, `404 ACCOUNT_NOT_FOUND`.

### `GET /v1/accounts/{account_id}/transactions` → `200`

See [Pagination](#pagination). Errors: `400 INVALID_PAGINATION`, `400 VALIDATION_ERROR` (invalid `type`, unknown
parameter, malformed id), `404 ACCOUNT_NOT_FOUND` (checked even when the account would have no rows).

### `POST /v1/transactions` → `201`

| Field          | Rule                                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `account_id`   | Required UUID of an existing account.                                                                                   |
| `type`         | Required. `credit` or `debit`.                                                                                          |
| `amount`       | Required. `0.01`..`1000000000000.00`, at most two decimals (more is rejected, not rounded). Number or numeric string.   |
| `reference_id` | Required. 1..128 characters, no leading/trailing whitespace, no control characters. Unique per account, case-sensitive. |
| `description`  | Optional, ≤255 characters. Trimmed; empty becomes `null`.                                                               |

```json
{
  "id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
  "account_id": "3f25…",
  "type": "credit",
  "amount": "50.00",
  "description": "Top-up",
  "reference_id": "inv-1001",
  "balance_after": "150.00",
  "transfer_id": null,
  "created_at": "2026-10-27T09:10:01.004Z"
}
```

`balance_after` is the account balance immediately after this transaction. Sets a `Location` header.

**Duplicate `reference_id` on the same account** returns `409 DUPLICATE_TRANSACTION`. Nothing is created, the balance is
unchanged, and `error.context.existing_transaction` holds the original transaction. The payload of the second request is
not compared (the first request wins). The same `reference_id` may be used on different accounts.

**Insufficient balance** returns `422 INSUFFICIENT_BALANCE` with
`context: { account_id, balance, requested_amount, shortfall }`. A debit equal to the balance is allowed.

### `GET /v1/transactions/{transaction_id}` → `200`

Identical to the body returned at creation. Errors: `400`, `404 TRANSACTION_NOT_FOUND`.

### `POST /v1/transfers` → `201`

| Field                    | Rule                                                                                                                                               |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `source_account_id`      | Required, existing account.                                                                                                                        |
| `destination_account_id` | Required, existing account, different from the source (`SAME_ACCOUNT`).                                                                            |
| `amount`                 | Same rules as for transactions.                                                                                                                    |
| `reference_id`           | Optional; generated (UUID) if omitted. Unique per source account across transfers, and must be unused as a transaction reference on both accounts. |
| `description`            | Optional. Defaults to `Transfer to {destination}` / `Transfer from {source}` on the legs.                                                          |

The debit and the credit are written in one database transaction together with the transfer row; if anything fails
nothing is persisted. Both legs appear in the accounts' histories as ordinary `debit`/`credit` rows linked by
`transfer_id`, sharing the transfer's `reference_id` and `created_at`.

```json
{
  "id": "0d9f…",
  "source_account_id": "A…",
  "destination_account_id": "B…",
  "amount": "30.00",
  "description": null,
  "reference_id": "tr-77",
  "created_at": "2026-10-27T09:12:00.000Z",
  "debit_transaction": {
    "account_id": "A…",
    "type": "debit",
    "amount": "30.00",
    "balance_after": "70.00",
    "transfer_id": "0d9f…",
    "…": "…"
  },
  "credit_transaction": {
    "account_id": "B…",
    "type": "credit",
    "amount": "30.00",
    "balance_after": "80.00",
    "transfer_id": "0d9f…",
    "…": "…"
  }
}
```

Errors: `400 VALIDATION_ERROR`, `404 ACCOUNT_NOT_FOUND` (`context.missing` lists every missing field),
`409 DUPLICATE_TRANSFER` (`context.existing_transfer`), `409 DUPLICATE_TRANSACTION`, `422 INSUFFICIENT_BALANCE`.

### `GET /v1/transfers/{transfer_id}` → `200`

Same body as at creation. Errors: `400`, `404 TRANSFER_NOT_FOUND`.

### `GET /health` → `200`

```json
{
  "status": "ok",
  "checks": {
    "database": { "status": "up", "latency_ms": 3 }
  },
  "version": "1.0.0",
  "uptime_s": 120,
  "timestamp": "…"
}
```

`503 SERVICE_UNAVAILABLE` (standard envelope, `context.checks`) when the database is unreachable.

### Immutability: other methods

Any other HTTP method on a known resource returns `405 METHOD_NOT_ALLOWED` with an `Allow` header and
`context.allowed_methods`. This is checked before the resource is looked up. There is no way to edit or delete a
transaction, transfer or account through the API, and the database rejects it too.

## Error catalog

| Code                     | HTTP | When                                                                                 | `context` / `details`                                    |
| ------------------------ | ---- | ------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| `VALIDATION_ERROR`       | 400  | Body, path or query failed validation                                                | `details[]`                                              |
| `INVALID_PAGINATION`     | 400  | `page` or `limit` invalid (wins as top-level code if `type` is also invalid)         | `details[]`                                              |
| `MALFORMED_JSON`         | 400  | Body is not valid JSON, or a bare scalar / `null`                                    |                                                          |
| `ACCOUNT_NOT_FOUND`      | 404  | Well-formed account id with no account                                               | `account_id`; transfers add `missing[]`                  |
| `TRANSACTION_NOT_FOUND`  | 404  | Unknown transaction id                                                               | `transaction_id`                                         |
| `TRANSFER_NOT_FOUND`     | 404  | Unknown transfer id                                                                  | `transfer_id`                                            |
| `ROUTE_NOT_FOUND`        | 404  | Unknown path, any method                                                             |                                                          |
| `METHOD_NOT_ALLOWED`     | 405  | Verb not supported on a known resource                                               | `allowed_methods`, `Allow` header                        |
| `DUPLICATE_TRANSACTION`  | 409  | `reference_id` already used on the account                                           | `existing_transaction`                                   |
| `DUPLICATE_TRANSFER`     | 409  | `reference_id` already used by a transfer from the source account                    | `existing_transfer`                                      |
| `CONCURRENCY_CONFLICT`   | 409  | Lock wait exceeded `DB_LOCK_TIMEOUT_MS`, or a deadlock/serialisation failure. Retry. | `Retry-After` header                                     |
| `PAYLOAD_TOO_LARGE`      | 413  | Body above `BODY_LIMIT`                                                              |                                                          |
| `UNSUPPORTED_MEDIA_TYPE` | 415  | Write without `Content-Type: application/json`                                       |                                                          |
| `INSUFFICIENT_BALANCE`   | 422  | Debit or transfer exceeds the balance                                                | `account_id`, `balance`, `requested_amount`, `shortfall` |
| `BALANCE_LIMIT_EXCEEDED` | 422  | Credit would overflow the largest representable balance                              | `account_id`                                             |
| `INTERNAL_ERROR`         | 500  | Anything unexpected. Generic message; details are logged with the request id.        |                                                          |
| `SERVICE_UNAVAILABLE`    | 503  | Readiness check failed                                                               | `checks`, `Retry-After` header                           |

## Validation rules

`details[].rule` values: `REQUIRED`, `INVALID_TYPE`, `INVALID_ENUM`, `INVALID_UUID`, `INVALID_AMOUNT`, `BLANK`,
`TOO_LONG`, `NOT_INTEGER`, `OUT_OF_RANGE`, `INVALID_CHARACTERS`, `INVALID_FORMAT`, `UNKNOWN_FIELD`, `SAME_ACCOUNT`.

| Field                                                                 | Rule                                                                      | Failure rule(s)                                                                         |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Body                                                                  | Must be a JSON object                                                     | `REQUIRED` (absent), `INVALID_TYPE` (array/scalar) on `body`                            |
| Any unknown key (body or query)                                       | Rejected                                                                  | `UNKNOWN_FIELD`                                                                         |
| `name`                                                                | String, trimmed, 1..100, no control characters                            | `REQUIRED`, `INVALID_TYPE`, `BLANK`, `TOO_LONG`, `INVALID_CHARACTERS`                   |
| `account_id`, `source_account_id`, `destination_account_id`, path ids | UUID in any case                                                          | `REQUIRED`, `INVALID_TYPE`, `INVALID_UUID`                                              |
| `type`                                                                | `credit` or `debit` exactly                                               | `REQUIRED`, `INVALID_ENUM`, `INVALID_TYPE`                                              |
| `amount`                                                              | Number or string matching `^(0\|[1-9]\d{0,12})(\.\d{1,2})?$`, > 0, ≤ 1e12 | `REQUIRED`, `INVALID_TYPE`, `INVALID_AMOUNT`                                            |
| `reference_id`                                                        | 1..128, not blank, no surrounding whitespace, no control characters       | `REQUIRED`, `INVALID_TYPE`, `BLANK`, `INVALID_FORMAT`, `TOO_LONG`, `INVALID_CHARACTERS` |
| `description`                                                         | Optional string ≤255, trimmed, no control characters                      | `INVALID_TYPE`, `TOO_LONG`, `INVALID_CHARACTERS`                                        |
| `page`, `limit`                                                       | Integers; `page` ≥ 1; `limit` 1..100                                      | `NOT_INTEGER`, `OUT_OF_RANGE`                                                           |

## Status-code policy

- `400` the request is malformed or fails validation. `404` something it names does not exist. `405` the verb is not
  allowed. `409` the request conflicts with existing state (duplicate, lock conflict). `422` the request is valid but a
  business rule rejects it (insufficient balance). `5xx` is never used for a client mistake.
- Insufficient balance is `422` rather than `409` so that `409` always means "this already exists / state conflict".
